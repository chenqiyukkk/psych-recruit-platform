# 成员4-软件测试与质量保证报告

## 1. 测试范围

成员4负责微信小程序核心功能与测试质量保证。本报告覆盖：

- 小程序首页实验列表、搜索筛选、分页加载。
- 实验详情、报名入口、筛选条件与排除标签展示。
- 微信授权登录优先、测试账号登录兜底。
- 个人中心、我的报名、通知中心、我的申诉。
- 与后端核心接口的联调验收：认证、实验、报名、签到、支付、评价、申诉。
- 测试资料交付：测试用例、缺陷跟踪、Postman 接口测试集合。

## 2. 测试策略

| 测试类型 | 工具/方式 | 覆盖目标 |
|---|---|---|
| 小程序静态结构测试 | Node.js `node --test` | 页面路由、WXML 文案、工具函数、接口封装 |
| 小程序语法检查 | `node --check` | JS 语法正确性 |
| 页面配置检查 | 自定义 Node 脚本 | `app.json` 页面声明与页面四件套存在 |
| 后端回归测试 | Maven + JUnit | 后端接口与业务规则 |
| 接口测试 | Postman 集合 | 登录、实验、报名、支付、评价、申诉主流程 |
| 手工验收 | 微信开发者工具 | 小程序 UI、交互、授权登录、页面跳转 |

- 代码已合并到成员4测试分支。
- 后端服务可启动或可在 test profile 下运行。
- 小程序 `app.json` 页面路径与页面文件完整。

- 测试账号或自动生成账号可用于登录验证。

## 5. 测试准出标准

- 测试用例执行覆盖不少于 50 条。
- 缺陷跟踪记录不少于 10 条，严重缺陷均已关闭或有处理说明。
- 小程序工具测试全部通过。
- 后端回归测试全部通过。
- Postman 集合覆盖核心业务链路，导入后可按变量执行。
- 测试准出结论明确。

## 6. 风险与质量控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 微信登录依赖 AppId / secret | 真机登录可能受环境影响 | 保留测试账号登录兜底，后端支持 mock 配置 |
| 小程序页面和后端接口字段不一致 | 页面展示异常或提交失败 | 对 `request.js` 与页面文案增加自动检查 |
| 筛选条件 JSON 直接展示 | 用户无法理解实验资格 | 在 `formatExperiment` 中统一解析为中文字段 |
| 申诉手填 ID 容易误填 | 用户无法知道目标记录 ID | 改为从已完成实验中选择 |
| 本地配置误提交 | 影响其他成员开发环境 | 检查 `project.private.config.json` 等本地文件 |
