# 成员4-小程序微信授权登录改造需求

## 1. 背景

当前微信小程序个人中心使用“用户名 + 密码”的登录方式，页面只提供登录表单，没有注册入口。这个方案虽然可以对接现有后端 `/api/auth/login` 接口完成基础调试，但不符合微信小程序的常见用户体验。

小程序端应改为微信授权登录：用户进入小程序后可以先浏览公开内容，在需要身份的操作场景中通过微信身份完成登录。首次微信登录时，系统自动创建或绑定平台用户。

## 2. 当前问题

1. 小程序个人中心存在用户名、密码输入框，不符合微信小程序登录习惯。
2. 小程序没有注册入口，导致新用户无法仅通过小程序完成首次使用。
3. 小程序登录依赖后端普通账号体系，不支持微信用户的 `openid` 绑定。
4. 报名、个人中心、通知等需要身份的操作没有统一的微信登录引导。

## 3. 改造目标

1. 小程序端改为“微信授权登录”按钮，不再使用用户名密码输入。
2. 后端新增微信小程序登录接口，保留原有普通登录/注册接口。
3. 首次微信登录自动创建默认“被试”用户。
4. 微信登录成功后仍返回 JWT token，现有报名、通知、个人中心接口继续通过 token 鉴权。
5. 未登录用户可以浏览实验列表和实验详情；报名、个人中心、通知等功能必须登录后使用。

## 4. 推荐交互流程

### 4.1 打开小程序

用户打开小程序后默认进入实验首页。

- 可以直接查看实验列表。
- 可以进入实验详情页查看公开信息。
- 不应一打开就强制弹出授权登录。

### 4.2 触发登录

以下操作需要登录：

- 点击“我的”进入个人中心。
- 点击实验详情页的“立即报名”。
- 查看“我的报名”。
- 查看通知。
- 后续的签到、支付确认、评价、申诉等操作。

未登录时应显示“微信授权登录”按钮或弹出登录引导。

### 4.3 微信登录流程

```text
用户点击“微信授权登录”
↓
小程序调用 wx.login()
↓
小程序获得临时 code
↓
小程序请求 POST /api/auth/wx-login
↓
后端调用微信 code2Session 接口换取 openid
↓
后端按 openid 查询用户
↓
不存在则自动创建默认“被试”用户
↓
后端生成 JWT token
↓
小程序保存 token 并进入个人中心
```

## 5. 后端改造需求

### 5.1 数据库

在 `users` 表增加微信用户标识字段：

```sql
ALTER TABLE users
  ADD COLUMN wechat_openid VARCHAR(128) NULL COMMENT '微信小程序 openid';

CREATE UNIQUE INDEX uk_users_wechat_openid ON users (wechat_openid);
```

如项目使用统一 schema 文件，需要同步更新：

- `database/schema/schema.sql`
- 根目录 `schema.sql`（如果仍作为交付 SQL 使用）

### 5.2 用户实体

文件：

- `backend/src/main/java/com/project/user/entity/User.java`

新增字段：

```java
private String wechatOpenid;
```

字段名和数据库列名建议保持清晰映射，可使用 `@Column(name = "wechat_openid", unique = true)`。

### 5.3 用户仓库

文件：

- `backend/src/main/java/com/project/user/repo/UserRepository.java`

新增查询方法：

```java
Optional<User> findByWechatOpenid(String wechatOpenid);
boolean existsByWechatOpenid(String wechatOpenid);
```

### 5.4 配置

文件：

- `backend/src/main/resources/application.yml`

新增配置项：

```yaml
wechat:
  miniapp:
    app-id: ${WECHAT_MINIAPP_APP_ID:}
    app-secret: ${WECHAT_MINIAPP_APP_SECRET:}
```

说明：

- `app-secret` 不应写死在代码仓库中。
- 本地开发可以通过环境变量配置。
- 若课程演示暂时没有真实 AppID，可提供 mock 模式或测试配置，但正式逻辑要保留真实微信登录入口。

### 5.5 DTO

新增请求 DTO：

```java
public class WxLoginRequest {
  @NotBlank
  private String code;
}
```

响应可以复用 `AuthLoginResponse`，也可以新增：

```java
public class WxLoginResponse {
  private String token;
  private UserProfileResponse profile;
}
```

推荐返回 token 和 profile，方便小程序登录后立即渲染个人中心。

### 5.6 登录接口

文件：

- `backend/src/main/java/com/project/user/controller/AuthController.java`

新增接口：

```text
POST /api/auth/wx-login
```

请求示例：

```json
{
  "code": "wx.login 返回的临时 code"
}
```

响应示例：

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "token": "JWT_TOKEN",
    "profile": {
      "id": 1,
      "username": "wx_xxxxxxxx",
      "role": "被试",
      "reputationScore": 100
    }
  }
}
```

### 5.7 Service 逻辑

文件：

- `backend/src/main/java/com/project/user/service/UserService.java`

新增微信登录方法，核心逻辑如下：

```text
1. 校验 code 非空
2. 调用微信 code2Session 接口
3. 获取 openid
4. 根据 openid 查询用户
5. 如果用户不存在：
   - 创建新用户
   - role = 被试
   - reputationScore = 100
   - username 可生成 wx_ + openid 后 8 位，或 wx_ + 随机串
   - password 可为空或设置不可登录占位值
6. 调用 JwtUtil 生成 token
7. 返回 token 和用户资料
```

微信接口地址：

```text
https://api.weixin.qq.com/sns/jscode2session
```

请求参数：

```text
appid
secret
js_code
grant_type=authorization_code
```

### 5.8 保留原登录注册接口

不建议删除现有接口：

- `POST /api/auth/register`
- `POST /api/auth/login`

原因：

- Web 管理端可能仍需要用户名密码登录。
- Swagger/API 测试仍可使用普通账号。
- 自动化测试中已有注册登录流程。

小程序端改用 `/api/auth/wx-login` 即可。

## 6. 小程序改造需求

### 6.0 UI 优化要求

成员4小程序端应同步优化视觉层次，避免页面像临时测试表单。推荐方向：

1. 首页使用更明确的招募看板风格，突出“实验列表”和“招募中数量”。
2. 卡片使用白底、浅边框、低强度阴影，减少大面积米黄色。
3. 主色使用墨绿色，辅助色使用金色或暖橙色强调报酬。
4. 个人中心未登录态优先展示“微信授权登录”，测试账号登录作为折叠的调试入口。
5. 按钮、状态标签、输入框保持 12rpx 左右圆角，视觉上统一。
6. 页面文字避免拥挤，卡片内标题、状态、时间、地点、报酬要分层展示。

### 6.1 接口封装

文件：

- `miniprogram/utils/request.js`

新增：

```js
wxLogin(data) {
  return request({
    path: '/api/auth/wx-login',
    method: 'POST',
    data,
    auth: false,
  });
}
```

### 6.2 个人中心页面

文件：

- `miniprogram/pages/profile/index.wxml`
- `miniprogram/pages/profile/index.js`
- `miniprogram/pages/profile/index.wxss`

改造要求：

1. 移除用户名输入框。
2. 移除密码输入框。
3. 登录按钮改为“微信授权登录”。
4. 增加提示文案：“首次登录将自动创建被试账号”。
5. 点击按钮后调用 `wx.login()`，再请求后端 `/api/auth/wx-login`。
6. 登录成功后保存 token，并加载个人中心信息。

前端逻辑示例：

```js
loginByWechat() {
  wx.login({
    success: (res) => {
      if (!res.code) {
        wx.showToast({ title: '微信登录失败', icon: 'none' });
        return;
      }
      api.wxLogin({ code: res.code })
        .then((result) => {
          getApp().setToken(result.token);
          this.setData({ token: result.token });
          return this.loadDashboard();
        });
    },
  });
}
```

### 6.3 报名按钮登录拦截

文件：

- `miniprogram/pages/experiment-detail/index.js`

改造要求：

1. 点击“立即报名”前先检查 token。
2. 未登录时跳转到个人中心或弹出登录引导。
3. 已登录时再调用报名接口。

示例：

```js
if (!getApp().getToken()) {
  wx.switchTab({ url: '/pages/profile/index' });
  return;
}
```

### 6.4 首页和详情页

实验首页和实验详情属于公开内容，建议不强制登录。

要求：

- 未登录也能浏览实验列表。
- 未登录也能查看实验详情。
- 只有执行报名操作时才触发登录。

如后端当前对 `/api/experiments` 仍要求认证，需要后端安全配置同步放开实验查询接口。

## 7. 权限与安全要求

1. `openid` 不返回给前端展示。
2. `app-secret` 不写入代码仓库。
3. token 仍保存在小程序本地 storage 中。
4. 登录失败时给出明确提示，例如“微信登录失败，请稍后重试”。
5. 微信接口异常时后端返回统一错误格式。

## 8. 测试与验收

### 8.1 后端自动化测试

需要新增或更新测试：

1. `wx-login` code 为空时返回错误。
2. 微信 code 换取 openid 成功时，新用户自动创建。
3. 同一个 openid 第二次登录不重复创建用户。
4. 微信登录成功后返回 JWT token。
5. 原 `/api/auth/login` 和 `/api/auth/register` 仍然可用。

后端测试命令：

```powershell
mvn -f backend\pom.xml "-Dspring.profiles.active=test" test
```

验收标准：

```text
BUILD SUCCESS
Tests run: ..., Failures: 0, Errors: 0
```

### 8.2 小程序基础测试

小程序现有工具测试仍需通过：

```powershell
node --test miniprogram\tests\miniprogram-utils.test.js
```

需要补充测试：

1. `request.js` 中 `wxLogin` 路径正确。
2. 未登录报名时不会直接请求报名接口，而是进入登录流程。

### 8.3 手动验收

使用微信开发者工具打开：

```text
D:\软工大作业\psych-recruit-platform\miniprogram
```

验收步骤：

1. 打开小程序，默认进入实验首页。
2. 未登录状态下可以浏览实验列表。
3. 未登录状态下可以打开实验详情。
4. 点击“我的”，显示“微信授权登录”按钮，而不是用户名密码输入框。
5. 点击“微信授权登录”，登录成功后进入个人中心。
6. 个人中心显示用户角色、信誉分、报名记录、通知入口。
7. 退出登录后，再次进入个人中心重新显示微信登录入口。
8. 未登录点击“立即报名”时，引导登录。
9. 登录后点击“立即报名”可以正常提交报名。

## 9. 影响范围

涉及模块：

- 后端用户认证模块
- 后端用户实体和数据库 schema
- 小程序个人中心页面
- 小程序实验详情报名逻辑
- 小程序接口封装
- 自动化测试和手动验收流程

不应影响：

- Web 管理端用户名密码登录
- 已有 Swagger/API 测试账号注册登录
- 现有 JWT 鉴权方式

建议从最新 `develop` 新建功能分支：


```text

```

## 11. 完成标准

满足以下条件才算完成：

1. 小程序个人中心不再出现用户名密码登录表单。
2. 小程序可以通过微信登录获得 token。
3. 首次微信登录可以自动创建平台用户。
4. 已登录用户可以查看个人中心、我的报名、通知。
5. 未登录用户报名时会被引导登录。
6. 后端测试通过。
7. 小程序工具测试通过。
8. PR 合并到 `develop`。
